# 人物生图链路

本轮改造覆盖人物聊天发起的生图。保留现有图片供应商适配、Gemini 原生流式语言请求，以及人格原文作为聊天唯一系统提示词的约定。

## 参考来源

阅读并参考以下源码的职责划分，未引入 AstrBot 运行时或复制插件的服务商实现：

- Gitee AIImg：<https://github.com/muyouzhi6/astrbot_plugin_gitee_aiimg>，阅读版本 `6d683ab1d2b53c66b13a2f7d20f63450953a5791`。主要参考 `core/background_tasks.py`、`core/image_task_parser.py`、`core/provider_chain.py`、`core/reference_subject.py` 以及后台任务设计文档中的接单、固定输入、进度查询和结果通知。
- OmniDraw：<https://github.com/diaomin66/astrbot_plugin_omnidraw>，移植版本 `670d021893be018ba2fbbb21b7bd85d250c59188`。使用 `core/prompt_optimizer.py` 的五套风格预设、单图／多图系统提示词原文、七字段结构、拼接顺序、防拼贴前缀和失败回退。

## 执行过程

1. 聊天模型调用 `generate_image`，提供模式、提示词、参考图及用途、模型、全部生成参数和是否允许副脑优化。
2. 校验模型能力、参考图存在性、遮罩、数量及参数兼容性。人物设置中的固定画幅在接单时落实：竖图 2:3、方图 1:1、横图 3:2；Gemini 使用 `aspect_ratio` 并保留分辨率档位，其他图片接口使用像素 `size`。自动画幅保留模型指定参数。有效参数随任务保存，后续设置变化和失败重试不改变已接单画幅。`selfie` 将人物固定参考图放在最前，额外参考按明确用途排列。头像不参与。
3. 任务写入 IndexedDB，同时固定请求和配置快照、读取参考图字节。任务不再依赖后续可变的人物或聊天状态。
4. 默认后台模式返回 `{ accepted: true, taskId, status, requestedCount }`。这只是接单，不代表已经生成图片。主模型可继续流式回复，用户可继续聊天。
5. 队列最多同时执行两个任务，最多接受八个未完成任务。任务内的多张图片并发执行，每张独立请求副脑和生图；哪张提示词先完成就先提交生图，不等待其他副脑或图片。参考图最多八张，每张最多 20 MB，合计最多 64 MB。
6. 主 Agent 的 `generate_image.prompt` 原样作为副脑唯一用户输入，单图副脑系统提示词使用 OmniDraw 原文；多图每张使用单图预设，加上该张序号、允许变化的方向和重复时需避开的已用提示词；不附加参考图、人格或聊天历史，不使用工具。主 Agent 负责在提示词中写明主体、场景及参考图用途。可独立选择 OpenAI Responses 或 Gemini 原生流式语言接口、模型、风格和超时。
7. 每张副脑独立返回一个 JSON 对象，并发生成多份方案。旧格式兼容 `results` 数组。按 `subject_appearance`、`clothing_and_accessories`、`pose_and_action`、`environment_and_scene`、`lighting_and_mood`、`technical_specs`、`realism_and_quality_guardrails` 的顺序拼接，并使用上游防拼贴前缀和空白压缩。兼容完整代码围栏和根数组；多图不复制首个提示词补足数量。最终提示词完全重复的槽位最多额外请求副脑两次，仍重复则本张失败，不重复提交生图。单图的截断／无效 JSON 或超时继续回退主 Agent 提示词；多图该张副脑失败则只标记该张失败，其他图片继续。用户取消不继续生成。
8. 将副脑整理出的各张最终字符串分别以 `n=1` 并发提交生图，不再追加原始要求、人格、参考图用途或额外画风。参考图与遮罩通过图片参数独立传递。主 Agent 提示词与每张最终生图提示词仅保存在内部任务记录中。
9. 每张后台图片完成后作为新的图片消息出现在对话末尾，不插回较早的消息。使用任务和图片序号组成固定消息 ID，确保刷新或重试不重复投递。通知等待当前聊天回复结束，再由原人物结合照片和话题自然接话。通知只提供数量和图片 ID，不包含优化提示词、参数及底层错误，且不提供生图工具。

聊天界面只展示用户与人物的文字、图片和简洁的输入指示。移除所有图片任务卡片、进度、成功提示、接口错误、提示词详情、图片描述以及再次生图按钮。旧记录的内部任务数据仍保留，但不在聊天中呈现。聊天唯一系统提示词仍为人格原文；工具描述和内部回执约定不向用户播报任务过程。

关闭后台生图后，带模式或副脑的请求仍共用任务执行器，等待任务结束再返回函数结果。旧格式、关闭副脑的同步调用保留兼容路径。

副脑默认使用「手机日常原生感」，其余预设为「自拍专用极致真实」「电影级光影大片」「日系插画大师」「3D 潮玩盲盒」。旧版 `follow` 升级为默认预设。自定义模式沿用上游结构，但保留用户实际输入的中文风格描述。多图的每个副脑请求使用独立的单图等待上限。

与上游的适配差异：语言请求复用本项目客户端（Gemini 为原生 SSE，副脑启用 JSON 输出模式），不复制 AstrBot 或 Chat Completions 客户端。不强行提取截断 JSON 中的残缺字段。任务最终提示词生成后直接交给生图；重试时保留已保存的有效独立提示词，仅未规划成功或重复的槽位重新请求副脑。旧任务同样保留成功图片。

## 按聊天要求生成多张

- 主 Agent 根据用户要求设置 `params.n`，数量表示独立图片张数，区别于人物数和参考图数。未指定数量的单图请求使用 1；只说“几张／多张”时可先给 2 张。每次调用的配置说明包含数量上限，Gemini、OpenAI 为 10，fal 为 4。
- 同主题多图，例如“发 3 张不同姿势的自拍”，一次调用 `n=3`；提示词描述共同主题和允许的变化。并发请求 3 次副脑，每次设计一张独立画面，提示词就绪后立即用 `n=1` 提交对应图片请求；三张生图可以同时进行，按实际完成顺序送入聊天。
- 用户逐张指定画面，例如“咖啡馆、河边、卧室各一张”，主 Agent 分别调用 3 次，每次 `n=1`，每份提示词只描述对应画面，分别交给副脑优化后直接生图。所有调用累计数量对应用户要求，已接单数量计入总数。
- 数量与规划规则放在工具说明中；聊天系统提示词仍只使用人格原文。无需额外数量栏，聊天继续只显示文字和图片。
- 用户要求“再来／换一张”时主 Agent 重新设计画面。不同聊天轮次各自接单，不复用上一轮任务；图片接口若返回与本对话已有生成图内容完全相同的图片，会以原提示词和参数再请求一次，仍重复则记为该张失败，不重复发送旧图。多图中也执行此检查，成功图片继续保留。

## 模式与参考图

- `draw`：生成新图，可以无参考，也可以明确选择参考。
- `edit`：至少选择一张 `subject` 图片，只改用户要求的部分。
- `selfie`：使用人物固定参考图保持身份，可加入物体、服装等参考。没有人物参考图时明确失败。
- 用途：`identity`、`subject`、`style`、`clothing`、`object`、`pose`、`background`，与参考 ID 一一对应。同图的不同用途保留各自位置。
- 历史图片只使用模型明确选择的 ID，不自动沿用上一轮额外参考。缺图不会静默省略或降级纯文生图。
- 普通聊天仅提供固定人物参考图 ID 和外貌文字，不读取或上传固定参考图；副脑继续仅接收主 Agent 提示词。实际生图才读取所选参考图原图并发送给图片接口。用户在聊天中主动发送的图片、人物已送达的照片仍可用于看图对话。
- 固定参考图丢失不会阻塞普通聊天；实际生图时仍校验参考图是否存在，不静默省略。
- 遮罩作用于第一张 `subject` 图片；模型不支持的参数直接报错。
- 人物生图的透明输出使用原生 `background: transparent` 和 PNG 参数，不追加绿幕提示词或进行本地抠色，以保持最终提示词直接传递。Gemini 不支持透明输出。

## 状态、查询和恢复

`queued → optimizing → generating → completed / partial / failed / cancelled`

- `image_task_status` 只查询当前对话。默认返回状态和数量；`detail=true` 返回原始请求、方案、实际参数和逐张结果。
- 聊天上下文包含最近任务摘要，不默认重复塞入完整提示词。
- 取消任务会通知所有进行中的副脑和生图请求，等待子请求退出后释放队列名额，保留已完成图片。重试使用已保存的有效独立提示词和参数，只处理未完成项；同一工具调用重复接单返回原任务。
- 页面刷新或关闭会终止浏览器内执行。恢复时标记 `interrupted`，保留图片与方案，由用户重试未完成项。这里不是独立于浏览器存活的服务端任务系统。
- 语言回复失败不会清除已生成图片；重试回复复用已接单任务或成功工具结果。
- 任务、参考图和图片随人物数据备份导出，受图片回收保护。存在活动任务时，清理／导入／导出与人物删除遵循现有活动任务限制。

## 对话日志

人物对话右上角的活动图标打开独立「对话日志」弹窗，聊天界面不显示生图详情。日志从本次更新后新发生的操作开始记录，支持聊天／工具／副脑／生图筛选、异常筛选、内容搜索、展开详情、复制单条、导出当前筛选结果 JSON 和清空当前对话日志。

- 聊天：用户消息、主 Agent 实际请求（Gemini 原生 JSON / OpenAI Responses）、流式接收文本、完整回复、首字等待时间、请求总耗时、停止与失败、图片送达后的继续对话。
- 工具：函数名、原始参数、接单回执、状态查询结果、重试时复用结果、参数校验错误。
- 副脑：主 Agent 提示词、实际纯文本请求、模型和风格、原始输出、各张最终提示词、耗时、跳过、回退或取消。
- 生图：接单与排队、参考图 ID／用途／字节数、逐张开始、实际请求（Gemini、标准 OpenAI JSON / multipart / Responses）、图片 ID 与实际尺寸、失败、重复图重试、送达和任务最终结果。其他供应商至少记录应用传入的提示词与参数。

日志单独存于浏览器 localStorage，不进入人格、语言上下文或备份。全体对话合计保留最近 500 条，最多约 2 MB 字符内容，过长文本会标注截断。流式日志最多每 500 ms 更新一次，保存合并写入；页面关闭前保存，刷新时尚未结束的步骤标记为中断。认证字段、URL 密钥、签名和图片 Base64 清洗后才进入日志，导出与复制使用同一清洗后数据。存储失败只提示日志未保存，不阻塞聊天。清空日志不影响聊天，删除对话／人物或清空全部任务数据会同步清除对应日志。

## Gemini 兼容修复

- 语言请求发送前和流式结果接收时统一校验 `Part`，清理空占位块，兼容下划线字段。只有 `thoughtSignature` 的块保留独立位置并补上 `text: ''`；不合并或丢弃签名。历史记录在重试发送时也经过相同处理。
- 语言流接受 `finishReason: STOP`、兼容字段 `finish_reason: STOP` 和 SSE `[DONE]`。副脑明确请求 JSON 模式时，正常读完但缺少结束标记的响应，只要文本是完整 JSON 且没有函数调用，可继续进入方案校验。网络读取异常、取消、`MAX_TOKENS`、拦截、截断 JSON 仍然失败；聊天工具调用不使用这个 JSON 放宽路径。
- 图片解析同时支持 `inlineData` / `inline_data`、JSON 数组、流式事件、结果包裹、文件图片链接和文本中的明确图片数据；跳过带 `thought: true` 的中间图。
- 人物图片保存时复用 `storeImageWithSize` 读取真实宽高，逐图记录实际像素尺寸及比例，覆盖接口回填的请求值；不裁切或拉伸图片。真实尺寸与标准比例偏差小于 1% 时归为该比例，非标准比例保留真实像素尺寸。
- 未返回图片时，内部错误保留 `finishReason`、拦截原因、模型版本及有限长度的文字说明，人物聊天不直接展示这些技术信息。只收到文字、被拦截或输出截断不会被当成成功。
- 生图请求使用 `TEXT` 与 `IMAGE` 输出模态，Flash 推理等级使用原生枚举 `MINIMAL` / `HIGH`。

验证命令：先执行 `npm run build`，再执行 `npm test`。浏览器测试以模拟接口验证传输和任务行为，不代表真实模型出图质量。

本次验证：构建通过，56 个测试文件、611 项测试通过。五套上游预设的单图／多图提示词共 10 项逐字比对一致；浏览器验证了完整 JSON 缺少结束标记仍能优化、提示词逐字直传、后台聊天、图片按送达顺序追加、任务状态和技术详情不显示、部分失败重试不重复投递及刷新恢复。

## 人物聊天的流式显示与请求体优化

- Gemini 语言请求继续使用原生 `streamGenerateContent?alt=sse`。正文分片到达即触发显示回调，思考内容和函数参数保持内部处理。
- 修复原先 150 毫秒节流只有立即更新、没有尾部补刷的问题：首段立即显示，后续分片以最多约 40 毫秒间隔合并显示；连接暂停时也会显示已收到的全部正文。取消或出错时保存已收到的尾部文字，清理计时器。
- 收到 Gemini 的 `finishReason` 后结束读取，不再等待中转关闭 HTTP 连接；`MAX_TOKENS` 等异常结束仍报错，函数签名保持原样。
- 语言看图使用单独缓存的副本：大于约 512 KB 的静态图按原比例缩小到最长边 1536，并使用 JPEG 0.85 压缩；小图和 GIF 保持原样。参考图及历史图片并行准备。生图仍读取原始图片，原图存储和下载不变。
- 使用本地同一人物的两张参考图测量，请求体从 10,782,827 字节降到 487,595 字节。两次真实请求均在响应头返回前失败，因此没有取得可比较的真实首字时间。临时诊断代码和监听服务已移除。
